## 1. 目标与范围

本轮处理两项优化：

1. 完善 Claude Code、Claude 网页／桌面端 Skills 上传，以及 DeepSeek Harness 的 skill 安装与加载适配。
2. 适度合并重复规则、明确文件职责、按阶段读取参考资料，降低上下文负担与 token 用量，优先保证讲义效果。

用户已确认 Claude 的本地安装与网页／桌面上传两类入口均需支持；DSH 指 DeepSeek Harness。各宿主共用一套核心规则、脚本和模板，适配差异集中在安装、资源定位及必要的运行说明中。

本轮保留既有内容契约、整理模式与交付目标。只有安装或结构调整确需修改接口时，才说明原因、兼容方式和验证范围；其他功能优化另行规划。规划文档的提交与合并不代表启动实施，也不代表公开发布。

## 3. 保留的质量要求

- 保留原始输入与来源记录；公式、条件、推导、图表及有意义的边注都属于内容。
- 沿用用户明确的用途、整理权限、语言和样式；配置精简不能改变既有选择或编辑权限。
- 原文、解释性补充和更正保持可区分；不以常识补造模糊内容，不暗改题设，新增实质假设必须就地说明。
- 正文保持连贯、可独立复习；关键歧义就地提示，一般整理说明进入附录。
- 可辨认内容转录或可靠重绘；无法还原的必要局部截图仅作为附录证据，并保留原因与来源。
- 内容对照复核和最终页面复核分别执行；编译成功、结构校验通过不能代替实际查看。
- 恢复任务遵循当前状态和失效规则；部分完成、未复核和已复核结果继续区分。

关键要求在入口和高风险步骤可保留简短重复。以执行效果决定精简程度，不预设删减比例或 token 降幅。

## 4. 分阶段工作

以下阶段均为后续实施安排，当前尚未启动。

### O1 — 建立适配与规则基线

- 记录目标宿主的产品、版本、运行位置及安装方式。Claude Code 与网页／桌面端分别核对；DeepSeek Harness 以实际版本和对应来源为准，不直接套用其他同名工具的路径。
- Claude 网页／桌面端另核对面向使用者的官方上传帮助与运行限制，不用 Claude Code 或 API 的说明替代。
- 建立规则清单，记录每条重要要求的当前位置、重复位置、保留位置与读取时机。
- 记录入口和典型流程实际需要读取的文件及文本量，明确 token 统计方法；尚无运行数据时只记录静态量。
- 为后续对照保留同一套小型输入、任务要求和运行设置。材料限合成或授权范围明确的样例，私人材料留在本地忽略目录。

产物与完成条件：适配核对表、规则归属表和可复现基线记录齐全；未知能力有明确待核实项，不写成已支持。

### O2 — 完善安装与加载适配

| 入口 | 工作内容 | 需要分别取得的证据 |
| --- | --- | --- |
| Claude Code | 完善个人级和项目级安装、调用、更新与移除说明；检查完整目录安装及相对资源定位 | 独立环境可发现并调用 skill，脚本和参考文件可访问 |
| Claude 网页／桌面端 | 按目标产品要求提供可上传 ZIP 和操作说明；核对上传目录、工作目录、文件交付与依赖准备方式 | 上传与启用结果；实际图片读取、Python 调用、TeX／Poppler 能力及 PDF 输出结果 |
| DeepSeek Harness | 核对当前版本的发现目录、配置覆盖、调用方式和资源定位；补齐安装说明与必要入口 | 实际安装、发现、调用与资源访问结果 |

从同一核心目录生成分发内容，优先复用现有打包工具。仅在证据表明必要时调整包装或安装辅助脚本，不维护多套学术规则。

在临时或隔离目录验证安装，保留用户已有配置与自定义内容。缺少宿主、账号访问或运行依赖时记录具体缺口，继续完成可独立开展的工作；未运行的项目保持待验证。若平台限制影响既定 PDF 交付目标，先记录问题与解决选项，再确定兼容方案，不把上传成功当作完整适配成功。

产物与完成条件：安装说明与实际包装一致；安装发现、运行能力、端到端输出分项报告，既有 Codex 入口仍通过适用检查。

### O3 — 精简规则并调整读取结构

优先在现有文件内明确职责，只有确有按需读取收益时才拆分文件。

| 文件 | 主要职责 | 读取时机 |
| --- | --- | --- |
| `SKILL.md` | 触发范围、配置询问、关键质量约束、流程导航与必要工具入口 | 任务启动 |
| `references/workflow.md` | 材料理解、转录衔接、编译修复、恢复和复核顺序 | 执行相应阶段前 |
| `references/editorial.md` | 忠实版与复习版编辑边界、来源与解释的组织、正文及附录排版 | 整理正文与图表前 |
| `references/content-model.md` | 字段、枚举、默认值、来源引用和状态语义的权威定义 | 初始化、填写或修改相关数据前 |
| 学科与图表参考 | 会影响识别、推导组织和复核的专业规则 | 内容涉及对应学科或图表时 |
| `references/hosts.md` | 宿主特有能力、资源定位和兼容排错 | 安装、环境准备或相关故障时 |
| README、开发及发布文档 | 面向使用者的安装入口，以及工程检查、维护和发布记录 | 安装或维护时 |

- 配置询问集中在入口；字段默认值集中在契约；工作流引用已有选择，不再重述整段配置说明。
- 来源身份、补充解释与强调样式的组织集中在编辑规则；契约保留其字段约束。
- 修改后的恢复、重编译和复核顺序集中在工作流；字段与指纹含义保留在契约。
- 删去同义段落、过长背景和无助于决策的重复示例；保留真正能防止误读的例子。
- 将启动时无差别读取多份文档改为明确的阶段路由，保证必要规则在首次使用前被读取，避免引用链过深和反复打开文件。

产物与完成条件：规则归属表能逐项对应到调整后的内容；关键语义、模式权限和复核要求保留，所有链接及命令有效。

### O4 — 对照验证效果与开销

安装适配和规则精简分别验证，并保留对照证据。

| 层次 | 验证内容 | 结论边界 |
| --- | --- | --- |
| 文档与结构 | 链接、入口、包清单、规则对应、命令和资源路径 | 只证明文件与结构有效 |
| 工程运行 | 按实际改动运行现有相关检查；涉及编译、模板或包装时补充对应链路检查 | 合成输入只证明工程行为 |
| 宿主适配 | 安装／上传、发现、调用、图片读取、脚本执行、编译与交付 | 每个入口和版本分别记录，不互相代替 |
| 整理效果 | 对照原材料检查遗漏、符号与条件、推导衔接、图表含义和最终页面 | 小样结论限于所测范围，不代表完整课程验收 |
| 上下文与 token | 实际读取文件、重复读取、指令加载量；可获得时记录运行 token、耗时和重试次数 | 区分静态估算与实际消耗，不把文件变短等同于总成本降低 |

在同一宿主、模型及可控设置下比较精简前后，保留相同输入、请求和编辑权限。出现新增遗漏、来源混淆、复核跳过或阅读质量下降时，恢复相关规则或调整路由后复查；不以 token 节省抵消质量退步。

产物与完成条件：记录实际通过项、失败项和未验证项。只有对应宿主完成所列运行检查，才标为端到端通过；只有完成对照，才报告精简的效果与开销结论。
